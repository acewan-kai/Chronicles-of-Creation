## 第1步：PoC 技术验证（优先级最高）

### 目标
在一个**极限约束的封闭世界**中运行10个AI角色72小时，验证"世界自主运转→涌现叙事"这个核心假设是否成立。

### 具体任务

**1.1 创建封闭世界模型**
- 定义1个微型世界（如：一座孤岛上的村庄）
- 创建10个NPC角色，每人拥有：姓名、身份、性格简档、初始关系、1个短期目标
- 角色之间形成3-5条初始关系线索（敌对/友好/秘密）

**1.2 搭建最小可行沙盒引擎**
- 用 Python 实现简单的回合制模拟循环
- 每回合：每个NPC基于自身状态 + 环境 + 关系，调用 LLM 做出一个动作
- 动作输出格式：`{角色名}: {动作描述} → 影响 {目标角色/环境}`
- 记录所有动作为结构化事件日志（JSON Lines）

**1.3 接入LLM**
- 优先使用成本最低的可用模型（如 DeepSeek）
- 每个NPC使用独立的消息上下文
- 注入角色基本设定到 system prompt

**1.4 运行验证**
- 运行至少 100 个回合（模拟72小时）
- 收集事件日志
- 人工审阅：是否产生了**超出预设**的有趣互动？

### 验收标准（Go/No-Go）
| 条件 | 阈值 |
|------|------|
| 10个NPC全部存活运行100回合 | 必须 |
| 产生了至少3个非预设的跨角色互动 | 必须 |
| 至少1个互动具有"故事感"（可被想象成小说片段） | 必须 |
| 单回合延迟 < 15秒 | 期望 |

> ⚠️ 如果第1步不通过，**不要进入第2步**。重新调整角色设计或世界规则后重试。

## 第2步：P0 MVP 构建（7项核心需求）

### 前提条件
第1步 PoC 验证通过。

### 构建顺序（严格按此顺序，每完成一个模块再进入下一个）

```
A01 沙盒模拟核心
  ↓
A02 事件日志系统
  ↓
B01+B02 世界信息注入 + 知识图谱
  ↓
C01 智能体核心架构（记忆流 + 规划）
  ↓
F01 可视化世界观图谱（前端）
  ↓
G01 基础审美评分
```

### 各模块开发指令

#### A01：沙盒模拟核心
- 将 PoC 代码重构为正式架构
- 实现：世界状态管理、回合调度器、NPC动作执行器、事件分发器
- 技术选型：Python + asyncio（支持并发NPC推理）
- 配置系统：支持世界定义文件（YAML/JSON）

#### A02：事件日志系统
- 结构化存储所有NPC动作、世界状态变更
- 格式：JSON Lines，含时间戳、参与者、动作类型、影响对象
- 支持按时间范围/角色/类型查询
- 存储：本地 SQLite（MVP）/ 后续迁向量数据库

#### B01+B02：世界信息注入 + 知识图谱
- 实现 Lorebook 式动态词典：按关键字触发注入世界设定到LLM上下文
- 知识图谱：使用 NetworkX 存储势力、地点、法则、角色之间的关联
- 上下文预算管理：单次注入不超过总Token预算的30%

#### C01：智能体核心架构
- 每个NPC = 独立的智能体实例
- 记忆流：该NPC所见所闻的所有事件列表（最多保留最近N条）
- 规划模块：每N回合生成一次中短期计划
- 反思模块（简化版MVP）：周期性触发，总结最近行为模式

#### F01：可视化世界观图谱
- Web前端（React + D3.js 或 Cytoscape.js）
- 展示：角色关系网络图、世界地图（简化）、事件时间线
- 允许用户点击节点查看详情
- **注意**：第2步仅做"观察模式"，不可编辑

#### G01：基础审美评分
- 简单的文本质量评分（如基于规则：句式多样性、副词密度、情感词比例）
- 对每个生成的动作/事件给出 1-5 分
- 前端展示评分，供用户筛选高光时刻

### 技术栈建议

| 层 | 选型 |
|----|------|
| 后端框架 | Python FastAPI |
| 数据库 | SQLite（事件日志）+ NetworkX（知识图谱）|
| 前端 | React + Vite + Cytoscape.js |
| LLM接入 | OpenAI-compatible API（支持多模型切换）|
| 异步 | asyncio + aiohttp（并发NPC推理）|

## 第3步：Beta 测试准备

### 目标
P0全部模块可运行后，准备内部Alpha测试。

### 任务
- 创建3个预制世界模板（修仙/武侠/都市奇幻各一）
- 编写新用户引导流程（5步以内从注册到首个世界运行）
- 加入基础用量统计（模拟时长、事件数、LLM调用次数）
- 部署到测试服务器供内部团队试用

---

## 开发纪律

1. **每完成一个模块，运行一次端到端测试**（创建世界→运行10回合→查看日志→查看前端图谱）
2. **每天结束时确保代码可运行**，不留半成品
3. **Git提交粒度**：每完成一个子功能 commit 一次
4. **遇到阻塞立即记录**，先绕过去做下一个模块
5. **第1步PoC代码可以脏**，第2步必须重构干净
