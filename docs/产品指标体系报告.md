## 一、北极星指标（North Star Metric）

### 指标定义

> **月活跃创作者的"有效采纳章节数"（Monthly Adopted Chapters per Active Creator）**

### 核心公式

```
NSM = Σ(月度有效采纳章节数) / 月活跃创作者数（MAU-Creator）

其中：
- "采纳章节" = 用户审阅AI生成章节后选择"保留/发布"的章节（排除"重新生成"和"丢弃"操作）
- "有效" = 该章节在生成后30天内未被用户删除或回退
```

### 论证逻辑

**为什么选择这个指标而不是其他候选？**

| 候选指标 | 否决理由 |
|---------|---------|
| 月生成章节总数 | 包含大量用户不满意而重新生成的"废章"，无法衡量真实价值交付 |
| DAU | 高频打开不等于高产；创作者型工具的价值在于"产出"而非"浏览" |
| 月营收/GMV | 早期阶段应以价值验证优先于商业化，营收指标会扭曲产品方向 |
| 世界创建数 | 创建不等于持续使用，容易产生"注册农场"式的虚荣指标 |

**该指标的核心优势：**

1. **直接衡量核心价值交付** — 用户来平台的目的是"产出满意的文学作品"，采纳章节是该价值的直接量化
2. **天然平衡质量与数量的张力** — 盲目追求数量会降低采纳率，而仅追求采纳率可能导致过度保守；两者乘积迫使团队同时优化效率与质量
3. **可随产品阶段演进** — MVP期关注"是否有采纳"，成长期关注"采纳量与频次"，成熟期关注"采纳深度"（长篇连载率）
4. **与技术架构深度耦合** — 该指标直接受叙事提取引擎质量、P-RLHF审美对齐度、文本重写引擎表现影响，是技术栈健康状况的间接体检指标

### 拆解树（Driver Tree）

```
月活跃创作者有效采纳章节数
├── 月活跃创作者数
│   ├── 新创作者注册量 × 激活率
│   └── 存量创作者留存率
├── 人均月采纳章节数
│   ├── 人均月生成章节数
│   │   ├── 单次世界模拟时长
│   │   ├── 故事线并发行数
│   │   └── 章节生成速度（s/章）
│   └── 章节采纳率
│       ├── P-RLHF审美匹配度
│       ├── 叙事提取引擎戏剧价值召回率
│       └── 文本重写引擎文学质量评分
└── 有效系数（30天留存率）
    └── 长期满意度指标
```

## 二、关键KPI框架（AARRR + HEART混合模型）

### 2.1 获客（Acquisition）

| # | 指标名称 | 定义 | 数据源 | 优先级 |
|---|---------|------|--------|--------|
| A1 | 月新增注册创作者数 | 自然月内完成注册并验证邮箱的用户数 | 注册系统 | P0 |
| A2 | 渠道获客成本（CAC） | 各渠道总投放费用 / 该渠道新增创作者数 | 归因系统 + 财务 | P1 |
| A3 | 注册转化漏斗完成率 | 从落地页到注册完成的各步骤转化率 | 前端埋点 | P1 |
| A4 | 邀请码激活率 | 已有用户生成的邀请码被新用户激活的比例 | 邀请系统 | P2 |

### 2.2 激活（Activation）

| # | 指标名称 | 定义 | 数据源 | 优先级 |
|---|---------|------|--------|--------|
| B1 | 新用户首次世界创建完成率 | 注册后7天内完成至少1个世界初始化的用户比例 | 沙盒模拟器 | P0 |
| B2 | 首章TTV（Time to First Chapter） | 从注册到首次生成并采纳章节的中位时间 | 全链路事件日志 | P0 |
| B3 | 激活漏斗关键步骤流失率 | 注册→创世→配置智能体→首次运行模拟→首次生成章节→首次采纳 | 全链路追踪 | P1 |
| B4 | "啊哈时刻"触发率 | 用户首次在单次会话中连续采纳≥3个章节的比例 | 采纳事件流 | P1 |

### 2.3 留存（Retention）

| # | 指标名称 | 定义 | 数据源 | 优先级 |
|---|---------|------|--------|--------|

### 2.4 营收（Revenue）

| # | 指标名称 | 定义 | 数据源 | 优先级 |
|---|---------|------|--------|--------|

| D6 | 单位经济学（Unit Economics） | 单章节成本 vs 单章节平均收入 | 成本追踪 + 计费 | P0 |

## 三、核心模块数据埋点建议

### 3.1 沙盒模拟器（底层引擎，90%算力消费）

**这是成本结构的核心，也是最关键的数据源。**

| 埋点事件 | 参数 | 目的 |
|---------|------|------|
| `simulation.started` | world_id, agent_count, sim_config_hash, timestamp | 追踪模拟启动频次 |
| `simulation.step_completed` | world_id, step_duration_ms, active_agent_count, events_generated, token_consumed | 监控性能与Token消耗 |
| `simulation.agent_action` | world_id, agent_id, action_type, target_agent_id, action_context_hash | 智能体行为分析 |
| `simulation.interaction` | world_id, agent_a, agent_b, interaction_type, sentiment_score | 社交网络密度分析 |
| `simulation.event_generated` | world_id, event_id, event_type, importance_score, agents_involved[], token_estimate | 事件生产流水线 |
| `simulation.state_snapshot` | world_id, agent_states[], relationship_graph_hash, global_state_hash | 状态一致性验证 |

**技术关注点：**
- `step_duration_ms` 的P99延迟不得超过用户感知阈值
- `token_consumed` 按世界级聚合，作为成本核算基础单位
- `importance_score` 分布用于评估事件质量而非仅数量

### 3.2 叙事提取引擎（Story Sifting）

| 埋点事件 | 参数 | 目的 |
|---------|------|------|
| `sifting.session_started` | world_id, time_range_start, time_range_end, event_count_input | 提取会话追踪 |
| `sifting.candidate_identified` | world_id, event_sequence[], drama_score, coherence_score, archetype_match | 候选片段质量评估 |
| `sifting.storyline_created` | world_id, storyline_id, events_count, total_drama_score, sift_duration_ms | 故事线产出追踪 |
| `sifting.user_feedback` | storyline_id, user_action (accept/reject/refine), reason_code | 提取质量反馈闭环 |
| `sifting.vector_query` | query_type, query_dimension, result_count, latency_ms | 向量检索性能 |

**核心指标：**
- 戏剧价值召回率 = 被用户采纳的故事线 / 引擎推荐的候选故事线
- 提取效率 = `sift_duration_ms` / `event_count_input`
- 故事线精炼率 = 采纳后用户进一步手动调整的比例

### 3.3 文本重写引擎

| 埋点事件 | 参数 | 目的 |
|---------|------|------|
| `rewrite.requested` | storyline_id, style_preference, target_word_count, temperature | 重写请求追踪 |
| `rewrite.completed` | chapter_id, actual_word_count, generation_duration_ms, token_consumed | 产出效率与成本 |
| `rewrite.quality_check` | chapter_id, grammar_score, coherence_score, style_consistency_score, plagiarism_flag | 自动质量检测 |
| `rewrite.user_action` | chapter_id, action (adopt/regenerate/discard), edit_distance_if_edited, time_spent_reviewing | 用户满意度核心信号 |
| `rewrite.regeneration` | chapter_id, iteration_number, reason_selected, prompt_adjustment | 重生成因分析 |

**核心指标：**
- 章节采纳率（核心北极星组件）
- 平均编辑距离（低编辑距离 = 高质量输出 = 未来可减少重写Token消耗）
- 重生成因分布（帮助定位P-RLHF与重写引擎的改进方向）

## 四、商业可行性初步估算

### 4.1 成本结构模型

#### 核心成本驱动因素

```
单章节生成成本 = C_sim + C_sift + C_rewrite + C_jury

其中：
C_sim    = (模拟步数 × 活跃智能体数 × 平均Token/步/智能体) × LLM单价
C_sift   = (事件日志体积 × 向量检索次数) × (Embedding单价 + 检索单价)
C_rewrite = (平均输出Token数) × LLM单价 × 平均重写轮次
C_jury    = (评审团规模 × 每成员Token消耗) × LLM单价
```

#### 估算假设

| 参数 | MVP假设值 | 说明 |
|------|----------|------|
| 活跃智能体/世界 | 50-200个 | 随世界复杂度变化 |
| 平均模拟步/章节 | 500-2000步 | 取决于故事线发展 |
| 平均Token/步/智能体 | ~200 tokens | 含推理与动作输出 |
| 事件日志体积/章节 | ~500KB-2MB | 结构化JSON |
| 向量检索次数/提取 | 50-200次 | 取决于候选事件密度 |
| 输出字数/章节 | 2000-5000字 | 中文章节 |
| 平均重写轮次 | 1.5-3.0轮 | 含P-RLHF反馈迭代 |
| 评审团规模 | 3-7个虚拟评审 | 取决于审美模型复杂度 |

#### 单章节成本估算（人民币）

| 成本项 | 低价方案(DeepSeek/通义千问) | 中价方案(GPT-4o-mini混用) | 高价方案(GPT-4o/Claude) |
|--------|--------------------------|-------------------------|---------------------|
| 沙盒模拟 | ¥0.50-2.00 | ¥2.00-8.00 | ¥8.00-30.00 |
| 叙事提取 | ¥0.10-0.50 | ¥0.50-2.00 | ¥2.00-5.00 |
| 文本重写 | ¥0.05-0.30 | ¥0.20-1.00 | ¥0.80-3.00 |
| P-RLHF评审 | ¥0.05-0.30 | ¥0.20-1.00 | ¥0.80-3.00 |
| **单章节合计** | **¥0.70-3.10** | **¥2.90-12.00** | **¥11.60-41.00** |
| 存储/月/活跃世界 | ¥0.50-2.00 | ¥0.50-2.00 | ¥0.50-2.00 |

> **关键洞察：** 沙盒模拟成本占单章节总成本的60-75%，是成本优化的重点。混合使用低价模型处理常规模拟、高价模型处理关键叙事决策，可将成本压缩至纯高价方案的30-40%。

### 4.2 用户付费模型设计

#### 分层订阅模型

| 方案 | 月费 | 核心权益 | 目标用户 |
|------|------|---------|---------|
| **探索者 (Free)** | ¥0 | 1个活跃世界，3个智能体，月5章，基础风格 | 体验吸引，付费转化漏斗入口 |
| **创作者 (Standard)** | ¥49/月 | 3个活跃世界，20个智能体/世界，月30章，多风格 | 核心付费用户群 |
| **小说家 (Pro)** | ¥99/月 | 10个活跃世界，100个智能体/世界，月100章，P-RLHF完整训练 | 重度创作者 |
| **工作室 (Studio)** | ¥299/月 | 50个活跃世界，500个智能体，无限章节，API接入 | 小型创作团队 |

#### 单位经济学健康条件

```
健康阈值：ARPPU ≥ 3× 单用户月均成本

单用户月均成本 = 月均章节数 × 单章节成本 + 存储成本

例（Standard方案, 月30章, 中价方案）：
  成本：30 × ¥5 ≈ ¥150/月
  收入：¥49/月
  结论：付费方案需依赖用户实际生成量低于限额来实现盈利
```

**关键商业假设：**

1. **用量分布服从幂律** — 70%用户使用不到限额的50%，可借此优化实际服务成本
2. **成本随时间下降** — 随模型推理成本降低、工程优化（智能体复用、缓存策略），单章节成本有望年降30-50%
3. **Tokens-As-Revenue模型** — 未来可考虑"按Token计费"的灵活方案，直接对齐成本
4. **初期以价值验证优先** — MVP阶段可接受负毛利运营以换取用户数据和模型训练反馈

### 4.3 盈亏平衡预估

```
目标MAU        = 10,000 (成长期)
付费转化率      = 5-8%
月付费用户      = 500-800
ARPPU          = ¥60-80 (含方案分布)
MRR            = ¥30,000-64,000/月

月度总成本估算：
  LLM API      = 付费用户 × 平均章节 × 单章成本 = 600 × 20 × ¥4 = ¥48,000
  基础设施     = ¥5,000-10,000
  人力         = (按团队规模)
  
结论：成长期初期MRR与API成本接近持平，毛利改善依赖：
  ① 成本优化（模型降级、缓存、批处理）
  ② ARPPU提升（高阶方案占比提高）
  ③ 用户规模效应稀释固定成本
```

### 5.2 执行概览（CEO Dashboard）

**目标受众：** 创始人/产品VP，每日查看

| 卡片 | 指标 | 展示方式 | 预警规则 |
|------|------|---------|---------|

**阶段目标：证明有人愿意用AI"培育世界"的方式生成小说**
